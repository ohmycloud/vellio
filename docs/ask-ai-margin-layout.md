# 原生页边批注：可见性、对齐、完整回答与模型身份

## 根因与修复

- PDF 页边整列批注曾受正文高度限制并独立滚动，普通问题、笔记也会被卷入这个裁剪区域。移除整列的高度限制，只限制长 AI 回答的正文；普通批注按真实高度参与布局。长回答的滚动句柄及富文本实体按回答 ID 保留，虚拟列表重建后不会丢失内部阅读位置。仅实际溢出的回答拦截滚轮，短回答仍允许滚动文档。
- 独立 AI 回答缺少普通批注外侧的 12px 缩进。统一左右留白，并记录回答实际高度，避免后续批注使用估算高度而错误定位。
- 行尾丢字并不只是容器宽度问题：混合行内公式的排版器只为不同字体家族/字号重新测宽，忽略粗体和斜体，换行时按普通字体估宽，绘制时却用更宽的实际字形。因此文本仍保存在数据中，行尾却被视口裁掉。修正 `InlineFlow`，按实际字重/样式测量；普通强调保留词边界，超长词按 grapheme 拆分，不破坏 UTF-8。回答容器也明确使用可收缩的整列宽度。
- 批注抽屉的独立 AI 回答曾走另一套普通 Markdown 分支。现在与页边回答共用原生公式/代码渲染、模型标签及全文复制。

长回答在自身正文内滚动，“复制全文”始终复制完整原始回答。普通笔记可以自然增高，不再为了让下一页紧贴正文而裁掉笔记；长回答的总长度不会无限撑大页间空白。修改只涉及呈现和新回答元数据，不重提取书籍、不改旧批注坐标或回答正文。

## 实际模型与类型

- 记录响应模型与传输类型，分开保留 `requested_model` 以及原有线程的 profile ID，不修改用户的默认模型选择。
- OpenAI-compatible API 读取 SSE 的 `model`；Claude Code 读取结果 JSON 的 `model` 或唯一的 `modelUsage`；Codex CLI 读取 stderr 启动元数据中的 `model:`，到 `user` 提示分隔即停止，不从回答或提示词中猜测。
- CLI 元数据日志位于私有临时目录，结束、出错或取消后随临时目录清理，不将提示或诊断日志存入书库。读取 Codex 元数据最多 64 KiB。
- 聊天消息、对问题的回复、固定到页边的回答均保存并显示同一份身份，例如 `实际模型 · Codex CLI`。
- 旧回答若只存了 `default`，不能用今天的设置伪造历史来源；显示“模型与类型未记录”。新请求若服务端也未报告具体模型，显示“模型未报告 · 类型”。

## 验证

```sh
cargo test --locked --offline --lib --tests
RUST_MIN_STACK=16777216 cargo test --locked --offline --features desktop-ui-tests --bin easyread-gpui -- --test-threads=1
cargo test --locked --offline --manifest-path vendor/gpui-base/Cargo.toml --lib text::
cargo build --locked --offline --features desktop
```

新增回归：

- GPUI 窗口中实际发送滚轮事件：长回答可滚到末段，问题/笔记位置不变，重建虚拟行仍保留回答偏移，滚动文档后返回仍显示两条批注；短回答不吞掉文档滚轮。
- 原生页边及抽屉中的中英混排、粗体、行内公式、末段选择与全文复制；独立 AI 竖线和个人批注竖线处于同一左边界。
- 保留 PDF 长回复不会造成整页空洞、原/译/双语脚注连续性回归。
- 文本引擎：150/248/420px 下，实际粗体度量与行内原子对象混排，各片段不越过右侧裁剪边界，拼回的 UTF-8 文本完全相同。修复前此用例在 150px 列宽中生成 222.75px 的绘制宽度，修复后通过。
- 本地 SSE、模拟 Codex/Claude CLI 验证响应身份，覆盖保存/重开/固定、保留默认 profile，以及不把生成文本或提示中的假 `model:` 识别为元数据。不请求付费模型。

最终结果：库测试 178 项、集成/CLI 测试 79 项、桌面窗口测试 106 项、文本组件测试 204 项通过，共 567 项；12 个既有 `ignored` 用例按原配置未运行。应用及 vendor 的 Clippy `-D warnings`、桌面构建和 `git diff --check` 通过。构建仍有既有 macOS 链接器 `__eh_frame` 过大提示和 `block 0.1.6` 未来兼容提示，本轮未处理这些工具链警告。
